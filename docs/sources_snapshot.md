# Источники поставщика — снимок на Э1 (2026-08-02)

Заказчик подтвердил: эти две таблицы — **разовый срез**, не постоянный
канал поставки. Реальные источники подключаются позже (заказчик пришлёт
ссылки отдельно), `sources/base.py` рассчитан на добавление новых без
переделки. Но раз эти две таблицы реально доступны — построил парсеры под
них, чтобы `cli.py sources sync` можно было проверить на живых данных, а
не только на моках.

## `gsheets:solika_drop` — «Наличие и прайс Дроп СОЛИКА»

id `1OLviwwUxBYsK19_lqsMrfkzxCCDH39FActXHfn27_Ck`

- Данные с 6-й строки (0-based индекс 5), фиксированные колонки.
- Размеры: XS/S/M/L/XL/XXL, доступность как ✅/❌.
- **РРЦ в этой таблице нет вообще.** `pricing.py` (Э4) для товаров отсюда
  всегда идёт по фоллбэку «закупка + 1500».
- Две колонки цены: «Дроп цена / ВЫКУП» и «Дроп цена / БЕЗ ВЫКУПА».
  За `price_purchase` сейчас берём «ВЫКУП» — **не подтверждено с
  заказчиком, какая схема реально используется.** Уточнить до Э4.
- Формат самих цен в ячейке — солянка: `"3650₽  3500₽"`, `"5000 3850₽"`
  (без ₽ между числами), `"2 890₽"` (пробел — разделитель тысяч, причём
  неразрывный `\xa0`), изредка кириллическая `Р` вместо `₽`. Во всех
  случаях берём последнее число в ячейке — это актуальная (не
  зачёркнутая) цена. Разобрано и покрыто тестами в
  `sources/normalizer.py` / `tests/test_normalizer.py` — там же
  regression-тест на баг, когда наивный парсер схлопывал `"5000 3850"`
  в `50003850`.
- 31 строка после чистки пустых строк-заполнителей.

## `gsheets:best_dropship_hoodies` — прайс best_dropship, раздел «ХУДИ»

id `1xpkVr3iIZ_PeXRswfLpsHtKtfiKF5mZUQzfXyvVWw3A`

- Данные с 5-й строки (0-based индекс 4). Несмотря на первое впечатление
  (в сыром CSV-тексте много строк, похожих на заголовки секций), это
  **одна однородная таблица «Худи»**, а не несколько секций по типу
  товара — впечатление обманчиво из-за многострочных ячеек (перенос
  внутри `Название`, напр. `"ЗИП ХУДИ\nMARTINE ROSE\nx\nSUPREME"`),
  которые построчный `awk`/`grep` читает неверно. Разбирать такие CSV
  нужно через настоящий CSV-парсер (`csv.reader`), не построчным сплитом.
- Размеры: S/M/L/XL/2XL/3XL. Значение в ячейке — либо число (штук в
  наличии), либо 💎 (распродано). Есть строки, где 💎 во всех шести
  колонках — товар полностью распродан, но карточка в источнике
  всё равно есть. `sizes_available=[]` для таких строк, дальше решение
  за Э2 (`NEEDS_REVIEW`, заказчик уже согласовал такое поведение для
  позиций без доступных размеров).
- РРЦ есть, но заполнен не всегда.
- Последняя колонка — ссылка на пост в Telegram-канале поставщика,
  источник фото для Э3 (`media/fetch.py`), сюда фото не резолвим.
- 51 строка.
