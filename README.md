# avito_dvijenia

Автоматизация выставления и ротации объявлений на Авито для дропшипа одежды.

Система тянет прайсы поставщика, собирает из них карточки (товар × цвет × город),
отдаёт Авито XML-фид Автозагрузки, следит за просмотрами и, когда объявление
выпадает из топа выдачи, проводит **затирку** — подменяет всё содержимое карточки
на мусор и отправляет её в архив, чтобы можно было залить товар заново, не попав
под антидубль.

Подробности — в [docs/ROADMAP.md](docs/ROADMAP.md).
Правила работы над кодом — в [AGENTS.md](AGENTS.md).
Задачи и открытые вопросы — в [docs/BACKLOG.md](docs/BACKLOG.md).

## Важно понимать до запуска

Проект управляет **боевым аккаунтом с оборотом 200-220к**, тестового аккаунта нет,
а тариф — оплата за просмотры, то есть каждая опубликованная карточка тратит
деньги. Поэтому:

- **всё по умолчанию идёт в dry-run**, ничего не уезжает в Авито без явного
  подтверждения оператора в Telegram-боте;
- `make sync` и `make access` безопасны — они только читают;
- команды публикации появятся на этапе Э5 и будут спрашивать подтверждение.

Не обходи этот механизм (`core/approval.py`), он существует не для красоты.

## Быстрый старт

Код живёт в WSL. Требуется Python 3.12.

```bash
git clone <repo> && cd avito_dvijenia
cp .env.example .env      # заполнить креды, см. ниже
make setup                # venv + зависимости
make access               # проверить доступ к Avito API
make sync                 # стянуть прайсы поставщика (dry-run)
make check                # линт + тесты
```

### Что положить в `.env`

| Переменная | Где взять |
|---|---|
| `AVITO_CLIENT_ID`, `AVITO_CLIENT_SECRET` | ЛК Авито → Настройки → Для профессионалов → API |
| `AVITO_USER_ID` | подставится сам после `make access`, либо номер профиля |
| `TG_BOT_TOKEN` | @BotFather |
| `TG_OPERATOR_CHAT_ID` | написать боту `/whoami` |
| `GOOGLE_SERVICE_ACCOUNT_JSON` | путь к ключу сервис-аккаунта (кладём в `secrets/`) |
| `ADMIN_SHEET_ID` | id таблицы-пульта |

`.env` и `secrets/` в `.gitignore` и в репозиторий не попадают. Не убирай их оттуда.

## Команды

| Команда | Что делает |
|---|---|
| `make setup` | создать venv и поставить зависимости |
| `make check` | линт + тесты (гоняем перед коммитом) |
| `make test` | только тесты |
| `make lint` / `make fix` | проверить / автопочинить стиль |
| `make audit` | проверить, что секреты не утекли (перед `git push`) |
| `make access` | проверить доступ к Avito API, перегенерировать `docs/api_notes.md` |
| `make sync` | стянуть прайсы, показать диф (БД не трогается) |
| `make sync-write` | то же, но записать в БД |
| `make categories` | перегенерировать `docs/categories.md` из черновика |
| `make admin-sync` | синк таблицы-пульта: решения оператора + очередь модерации |
| `make media-sync` | скачать фото поставщика в MediaStore, показать диф (dry-run) |
| `make media-sync-write` | то же, но реально скачать и записать `MediaAsset` |
| `make content-build` | собрать `Listing` (5 гео-копий) для всех `APPROVED`-товаров |
| `make content-refresh-photos` | дозаполнить фото у уже собранных черновиков (dry-run) |
| `make bot` | запустить Telegram-бота |

Что не покрыто `make`, но есть в `python cli.py content --help`:
`content render --item <id>` (заголовок+описание всех 5 городов в консоль,
без записи в БД) и `content respin --item <id> --times N` (N перезаливов
описания с проверкой на самодубль по шинглам).

### Фото из выгрузки Telegram

Веб-превью канала отдаёт только последние ~20 постов, поэтому фото к
большинству товаров через сеть не достать (`B-018`). Обходной путь без
Telethon и кредов — выгрузка канала из Telegram Desktop (⋮ → Экспорт истории
чата, формат **HTML**, обязательно с фото):

```bash
python cli.py media export-report <папка выгрузки>   # что привяжется, ничего не пишет
python cli.py media sync --export <папка> --write    # взять фото оттуда
```

Привязка точная, по id поста из ссылки в прайсе (`t.me/<канал>/1545` ↔
`id="message1545"`). Строка «ссылка на пост есть, но поста нет в выгрузке»
в отчёте означает, что выгружен не тот канал или не тот период.

Если карточки уже собраны, фото до них само не доедет: `content build`
идемпотентен по (товар, город) и существующую карточку пропускает целиком.
Для этого есть `content refresh-photos [--write]` — дозаполняет фото у
`DRAFT`-карточек, опубликованные не трогает.

Всё, что не покрыто `make`, — через `python cli.py --help`.

## Карта модулей

```
core/        конфиг, схема БД, режим оператора (approval.py)
sources/     парсеры прайсов поставщика, сведение с прошлым синком
avito/       OAuth, HTTP-клиент API, категории, генерация фида
admin/       таблица-пульт и очередь модерации (queue.py, sheet.py)
pricing.py   формула цены: РРЦ+1500 либо закупка+1500
media/       фото: скачивание, уникализация, затирочные, хранилище
content/     заголовки, описания, синонимизация, гео-копии, humanize
lifecycle/   планировщик публикаций, детектор падения просмотров, затирка (Э5-Э7)
messenger/   чаты Авито, мост в Telegram                 (Э8)
bot/         Telegram-бот: подтверждения, алерты
web/         FastAPI: отдача /feed.xml и медиа           (Э5)
scripts/     обёртки для запуска, разовые проверки
docs/        роадмап, бэклог, факты про API и источники
```

Пустые пакеты — это ещё не сделанные этапы, а не забытый код. Что в каком
этапе — в [docs/ROADMAP.md](docs/ROADMAP.md).

## Статус

Сделаны Э0 (доступы, конфиг, API-клиент, режим оператора, скелет бота),
Э1 (источники поставщика), Э2 (админ-панель с очередью модерации,
двусторонний синк с таблицей-пультом), Э3 (медиа: скачивание фото,
уникализация, затирочное фото, pHash-реестр, MediaStore), Э4 (контент:
заголовки, 5 гео-шаблонов описания, синонимизация под перезалив,
humanize-линтер, маппинг размеров, сборка гео-копий) и Э5 (фид/бюджет/
планировщик/FastAPI — код и тесты готовы, живая публикация не
запускалась). Следующий — Э6, статистика.

Схема фида сверена с официальными шаблонами Авито из ЛК, фид собирается и
проходит локальную валидацию. Фото поставщика загружены выгрузкой канала:
**95 карточек (19 товаров × 5 городов) собраны с фото и ждут публикации**.

**Живая публикация пока заблокирована** — по делу, а не по недоделке;
блокеры `P0` в [бэклоге](docs/BACKLOG.md):

- `B-025` — нет публичного URL: Авито сам опрашивает наш `/feed.xml`,
  а `PUBLIC_BASE_URL` пуст и туннеля нет (`make tunnel` подскажет шаги);
- `B-024` — у обязательного поля `Delivery` неизвестно дословное значение.
  Заказчик сказал «авито-доставка», но в шаблоне списка нет, а Авито сверяет
  строкой. Закрывается одной командой, когда значение известно:
  `python cli.py categories-resolve-field Delivery "<точное значение>"`;
- `B-004` — токену не хватает доступа к autoload API: правильный путь найден
  (`/autoload/v2/reports`), но отдаёт 401.

Уже закрыты: Автозагрузка подключена, дневной лимит выставлен, `client_secret`
перевыпущен, категории сверены, фото загружены, `ADVANCE_RUB` выставлен,
планировщик проверяет бюджет (`B-026`). По `B-022` (размеры) рекомендация —
оставить как есть до пилота, цифры в бэклоге.
