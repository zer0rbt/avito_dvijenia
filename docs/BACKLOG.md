## Техдолг

### B-010 · goods_type не определяется автоматически
**Статус:** open · **Приоритет:** P1 · **Этап:** Э2/Э4

`SupplierItem.goods_type` (обувь / верхняя одежда) не заполняется ни одним из
источников — в таблицах этой колонки нет. Без него не выбрать категорию Авито
и не смаппить размерную сетку (у обуви и одежды они разные).

Осложняется тем, что в снимке большинство позиций — худи, футболки, шорты,
костюмы, то есть не «обувь» и не «верхняя одежда» в узком смысле. Нужно
решить, как их раскладывать по категориям Авито — вероятно, через
классификатор по названию плюс ручное доопределение в очереди модерации.

**Решение по Э2:** авто-правила очереди модерации (`admin/queue.py
evaluate_auto_status`) сознательно не проверяют `goods_type` — раз ни один
источник его не даёт, проверка увела бы 100% из 82 товаров в
`NEEDS_REVIEW`, что уже не фильтр, а его отсутствие. Классификатор по
названию остаётся открытым и нужен до Э4 (`avito/sizes.py` без него не
выбрать сетку размеров).

### B-012 · Эксперимент: схлопнуть затирку в один проход через DateEnd
**Статус:** open · **Приоритет:** P1 · **Этап:** Э7

Сейчас затирка спроектирована в два цикла Автозагрузки: первый применяет

### B-013 · Сеть WSL периодически не достукивается наружу
**Статус:** обойдено, причина не найдена · **Приоритет:** P2

Затрагивает как минимум два независимых направления:

- `httpx` к `docs.google.com` — `[Errno 101] Network is unreachable`, при том
  что `curl` из того же WSL в тот же момент отрабатывает;
- `git push` к `github.com:443` — таймаут после ~120 с, при том что с
  Windows-хоста тот же адрес отвечает 200.

То есть дело не в конкретном источнике, а в сетевом стеке WSL этого окружения
(вероятно, взаимодействие с VPN и IPv6-маршрутом).

Обойдено ретраями: `fetch_csv_rows()` — 3 попытки с бэкоффом,
`scripts/push.sh` — 5 попыток. Работает: последний push прошёл со второй.
Корневая причина не найдена. Если начнёт мешать сильнее — попробовать
принудительный IPv4 в httpx-транспорте и `git config --global http.version HTTP/1.1`.

### B-018 · `t.me/s/<channel>` отдаёт только последние ~20 постов канала
**Статус:** open · **Приоритет:** P1 · **Этап:** Э3

`media/fetch.py` резолвит фото товара через публичное веб-превью канала
(`fetch_post_photo_urls`), когда таблица не даёт прямую ссылку — так работает
для `best_dropship_hoodies` (колонка "ссылка на пост"). Подтверждено живым
прогоном `make media-sync`: из 82 позиций фото нашлось только у 2 — у
остальных `best_dropship`-товаров пост уже вышел за окно, которое отдаёт
превью канала (последние ~20 постов), и `fetch_post_photo_urls` штатно
возвращает пустой список, не ошибку.

Значит для основной массы товаров этого источника фото взять неоткуда без
дополнительного канала доступа. Варианты: (а) синкать фото сразу же, пока
пост свежий — тогда `sources sync` и `media sync` нужно гонять в одной
связке, а не независимо раз в сутки; (б) Telethon с реальным TG-аккаунтом
для доступа к полной истории канала (план такого использования как раз
избежал ради простоты — см. "Что проверено фактически"); (в) просить
поставщика присылать фото отдельным каналом/архивом. Решить до Э4 — без
фото карточка не публикуется (Автозагрузка требует `Images`).

### B-019 · У шаблонов описания нет рубильника "черновик/утверждено"
**Статус:** open · **Приоритет:** P1 · **Этап:** Э4

`content/build.py` использует `content/templates/*.j2` сразу, без проверки
согласования с заказчиком (в отличие от `avito/categories.py`, где
`verified: false` громко блокирует использование до сверки). Пока
`content build` создаёт только черновики в БД (`Listing`, не публикуется),
риска нет — но на Э5 (публикация в фид) неутверждённый текст может уехать
в реальное объявление. Сделать по образцу `require_verified()`: флаг
"шаблоны утверждены" в конфиге/БД, `avito/feed.py` (Э5) должен явно упасть,
если публикация запрошена, а флаг не выставлен. Связано с `B-007`.

### B-017 · sync_products_from_supplier_items считал "обновлено" всегда

источниках показал `обновлено: 81` из 82 — код применял и логировал

в `sources/reconcile.py` (`_row_changed`). Regression-тест:
`test_sync_is_idempotent_when_nothing_changed`.
